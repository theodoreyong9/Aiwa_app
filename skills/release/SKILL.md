# Publier une release

Tout ce que tu fabriques pour la personne part en release du dépôt sur lequel tu travailles. C'est ce que la page Fichiers de son téléphone liste.

1. Choisis le genre : `docs`, `image`, `video`, `app` ou `page`.
2. Étiquette (tag) : `<genre>-<nom-court>-<AAAAMMJJ>`, en minuscules, sans espace (ex. `docs-cv-20260701`).
3. Un seul fichier en pièce jointe, nommé clairement, avec la bonne extension.
4. Titre de la release : une phrase courte que la personne comprend sans contexte (« CV de Julie, version anglaise »).
5. Publie avec l'outil GitHub dont tu disposes (création de release avec pièce jointe) ; ne commite jamais le fichier produit dans le code.
6. Une correction demandée ensuite = une nouvelle release (nouvelle date dans le tag), pas une modification silencieuse de l'ancienne.
7. Termine par la consigne d'alerte du message (le widget saura que c'est prêt).

La qualité suit la demande : une lettre simple reste simple, un dossier soigné demande du soin. Ne rajoute rien qui n'a pas été demandé.
