Publier un contrat

Un contrat distribué n'a pas de machine qui l'exécute pour tout le monde : ce sont des règles, « état + événement → nouvel état », que chaque personne rejoue avec les événements qu'elle détient. Deux personnes qui ont les mêmes événements obtiennent le même état.

Écrire le contrat

Un fichier JavaScript qui déclare l'état de départ et un gestionnaire par type d'événement, avec defineContract (paquet aiwa-lib). Toute action qui compte (une voix, un transfert) est signée avec signedAction et vérifiée avec verifySignedAction dans le gestionnaire : un simple champ from ne prouve rien.


        
Les champs

        
    
          
  • Nom : ce que les gens liront (60 caractères au plus).
    • 
          
  • Version : 1, 1.1… (20 au plus). Une nouvelle version est un nouveau contrat, avec son propre identifiant.
    • 
          
  • Description : à quoi il sert, quels types d'événements il comprend (500 au plus).
    • 
          
  • Code : le fichier complet (50 000 caractères au plus). Il est publié en entier, pas seulement son empreinte : tout le monde peut le récupérer.
    • 
        

        
L'identifiant du contrat est celui de l'événement de publication : il dérive du contenu, donc il ne change plus. L'empreinte (SHA du code) permet de vérifier qu'un code est bien celui-là.

        
        
        
        
        
        
        
        
        
        
        

      

      

        
Utiliser un contrat dans tes autres fichiers

        
Le code publié est ton fichier de contrat. Dans un autre fichier de ton application, tu prends sa definition et tu la donnes à Contract, avec ton identité et le journal de ton wallet : tu envoies des actions et tu lis l'état.

        

        
Si le code vient d'un contrat publié par quelqu'un d'autre, ne l'exécute qu'après avoir comparé son empreinte à celle que tu as notée de confiance (verifyContractSource, ou registerVerifiedContract quand le contrat doit déplacer de l'AIWA). Un identifiant ou un nom ne prouvent rien : il n'y a pas de registre central, et chacun choisit à quels contrats il fait confiance. Dans « Contrats », « Lire l'état » charge le code ainsi : seulement s'il a exactement l'empreinte que tu as acceptée, dans un espace isolé sans réseau ni clé, et il lit les événements de ce téléphone.

Chercher un contrat

        
Par identifiant de contrat, par identifiant de créateur (le début suffit), ou par un mot du nom. Je cherche parmi ce que ce téléphone a reçu. Pour les contrats de quelqu'un d'autre, écris le dépôt de son profil (owner/nom) : je lis les contrats qu'il y a laissés, je vérifie leurs signatures, et « Garder » les ajoute à ce téléphone.
